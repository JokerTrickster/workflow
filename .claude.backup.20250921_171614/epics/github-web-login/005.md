# Task 005: Dashboard UI - 레포지토리 목록 표시 + 카드 컴포넌트

## Overview

인증된 사용자의 GitHub 레포지토리를 카드 그리드 레이아웃으로 표시하는 대시보드 페이지를 구현합니다. React Query를 활용한 데이터 페칭, shadcn-ui 컴포넌트 기반의 반응형 디자인, 그리고 효율적인 가상화를 통한 성능 최적화를 포함합니다.

### State Management with React Query
```typescript
// Query Keys
const repositoriesQuery = {
  all: ['repositories'] as const,
  lists: () => [...repositoriesQuery.all, 'list'] as const,
  list: (filters: RepositoryFilters) => [...repositoriesQuery.lists(), filters] as const,
};

// Data Fetching Hook
const useRepositories = (filters: RepositoryFilters) => {
  return useInfiniteQuery({
    queryKey: repositoriesQuery.list(filters),
    queryFn: ({ pageParam }) => fetchRepositories({ ...filters, page: pageParam }),
    getNextPageParam: (lastPage) => lastPage.pagination.has_next ? lastPage.pagination.page + 1 : undefined,
    staleTime: 5 * 60 * 1000, // 5분
    cacheTime: 15 * 60 * 1000, // 15분
  });
};
```

### Search & Filter Features
```typescript
interface RepositoryFilters {
  search: string;           // 이름/설명 검색
  language: string | null;  // 프로그래밍 언어 필터
  sort: 'updated' | 'created' | 'name' | 'stars';
  direction: 'desc' | 'asc';
  visibility: 'all' | 'public' | 'private';
}

// Debounced Search Hook
const useSearchRepositories = (initialFilters: RepositoryFilters) => {
  const [filters, setFilters] = useState(initialFilters);
  const debouncedSearch = useDebounce(filters.search, 300);
  
  const finalFilters = { ...filters, search: debouncedSearch };
  return { filters: finalFilters, setFilters };
};
```

- [ ] 모든 레포지토리 (public + private) 카드로 표시

- [ ] 레포지토리 카드 클릭 시 GitHub 새 탭 열기

### UI/UX Requirements
- [ ] 반응형 그리드 레이아웃 (1-4열 adaptive)
- [ ] 스켈레톤 로딩 상태 (초기 로드 + Load More)
- [ ] 빈 상태 처리 (검색 결과 없음, 레포지토리 없음)
- [ ] 에러 상태 UI (네트워크 오류, API 실패)
- [ ] 접근성 (키보드 네비게이션, ARIA 라벨)

### Performance Requirements
- [ ] 초기 페이지 로드 < 2초 (30개 카드 기준)
- [ ] 검색 응답 시간 < 500ms (클라이언트 캐시 활용)
- [ ] 메모리 사용량 최적화 (가상화 적용 시 1000+ 카드)
- [ ] 이미지 lazy loading (아바타, 언어 아이콘)

### Data Requirements
- [ ] React Query 캐싱 (5분 stale, 15분 cache)
- [ ] Optimistic updates (북마크, 스타 등)
- [ ] Background refetch (focus/online 이벤트)
- [ ] Error boundary 구현 (컴포넌트별 격리)

## Risk Mitigation

### Technical Risks
- **대량 데이터 성능**: 가상화 또는 페이지네이션

- **레이아웃 시프트**: 스켈레톤 정확한 크기 매칭

### UX Risks
- **로딩 시간**: 점진적 로딩 + 우선순위 기반 렌더링
- **검색 성능**: 클라이언트 필터링 + 서버 검색 조합
- **모바일 경험**: 터치 최적화 + 스크롤 성능
