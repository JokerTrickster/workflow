# Task: Implement Backend Work Logs Endpoints

## Description
Implement GET/POST `/api/v1/work-logs` and POST `/api/v1/work-logs/entry` endpoints on the backend to replace frontend API routes that currently handle work log file operations.

## Acceptance Criteria
- [ ] GET `/api/v1/work-logs?repository={repo}&date={date}` returns work log markdown content
- [ ] POST `/api/v1/work-logs/entry` creates or appends to daily work log file
- [ ] Backend reads/writes to `.claude/logs/{repository}/{date}.md` directory
- [ ] Markdown files include proper headers and formatting
- [ ] Path traversal validation prevents security issues
- [ ] Repository name validation matches current API route logic
- [ ] All endpoints tested with Postman/curl

## Technical Details
- **Implementation Location**: Backend `/api/v1/work-logs` routes
- **File Operations**:
  - Read markdown files from `.claude/logs/{repo}/{date}.md`
  - Create files with headers if not exists
  - Append entries with timestamps
- **Validation Logic**:
  - Repository name: alphanumeric, hyphens, underscores only
  - Date format: YYYY-MM-DD
  - Path traversal prevention (no `..` in paths)
- **Error Handling**:
  - 404 if work log not found
  - 400 for invalid repository/date
  - 500 for file I/O errors

## Dependencies
- [ ] Backend has access to `.claude/logs` directory
- [ ] Backend uses existing file I/O utilities (or implement if missing)

## Effort Estimate
- Size: M
- Hours: 4-6h
- Parallel: true (independent from other backend tasks)

## Definition of Done
- [ ] Endpoints implemented and return correct responses
- [ ] File I/O operations work correctly (create, read, append)
