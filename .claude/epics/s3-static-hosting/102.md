# Task: Implement Backend GitHub Merge Proxy

## Description
Implement PUT `/api/v1/github/repos/{owner}/{repo}/pulls/{number}/merge` endpoint to proxy GitHub PR merge operations, keeping GitHub PAT secure on backend.

## Acceptance Criteria
- [ ] PUT endpoint accepts merge parameters (merge_method, commit_title, commit_message)
- [ ] Backend uses server-side `GITHUB_TOKEN` (not exposed to frontend)
- [ ] Proxies request to GitHub API: `PUT https://api.github.com/repos/{owner}/{repo}/pulls/{number}/merge`
- [ ] Returns GitHub API response to frontend (status, body)
- [ ] Handles GitHub API errors (404, 403, 422) and returns appropriate status codes
- [ ] Tested with Postman using valid PR number

## Technical Details
- **Implementation Location**: Backend `/api/v1/github` routes
- **GitHub API Call**:
  ```
  PUT https://api.github.com/repos/{owner}/{repo}/pulls/{number}/merge
  Headers: Authorization: token {GITHUB_TOKEN}
  Body: { "merge_method": "merge|squash|rebase", "commit_title": "...", "commit_message": "..." }
  ```
- **Environment Variable**: Read `GITHUB_TOKEN` from backend env (not `NEXT_PUBLIC_GITHUB_TOKEN`)
- **Response Handling**:
  - 200 OK: PR merged successfully
  - 404: PR not found
  - 403: Permission denied
  - 422: PR not mergeable (conflicts, checks failing)
- **Error Handling**: Return GitHub's error response to frontend

## Dependencies
- [ ] Backend has valid `GITHUB_TOKEN` environment variable
- [ ] Backend can make HTTPS requests to GitHub API
