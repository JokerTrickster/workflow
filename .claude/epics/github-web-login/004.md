# Task 004: GitHub API - 레포지토리 데이터 가져오기 API 엔드포인트

## Overview

GitHub REST API를 프록시하여 인증된 사용자의 레포지토리 데이터를 가져오는 Next.js API 엔드포인트를 구현합니다. Supabase 세션 검증과 GitHub API Rate Limit 처리를 포함한 견고한 API 계층을 구축합니다.

## Technical Requirements

### API Endpoint Structure
```
GET /api/github/repositories
- Query params: page=1, per_page=30, sort=updated, direction=desc
- Headers: Authorization (Supabase JWT)
- Response: { repositories: Repository[], pagination: PaginationInfo, rateLimit: RateLimitInfo }
```

### Data Models
```typescript
interface Repository {
  id: number;
  name: string;
  full_name: string;
  description: string | null;
  language: string | null;
  stargazers_count: number;
  forks_count: number;
  updated_at: string;
  html_url: string;
  private: boolean;
}

interface PaginationInfo {
  page: number;
  per_page: number;
  total_count: number;
  has_next: boolean;
  has_prev: boolean;
}

interface RateLimitInfo {
  limit: number;
  remaining: number;
  reset: number;
}
```

### Authentication Flow
1. Supabase JWT 토큰 검증
2. Supabase에서 GitHub access token 추출
3. GitHub API 요청 시 access token 사용
4. Rate limit 정보 클라이언트에 전달

## Implementation Details

### File Structure
```
src/app/api/github/repositories/route.ts - Main API handler
src/lib/github-api.ts - GitHub API client utilities
src/lib/auth-utils.ts - Supabase session validation
src/types/github.ts - GitHub API type definitions
```

### Error Handling Strategy
- **401 Unauthorized**: Supabase 세션 만료 또는 무효
- **403 Forbidden**: GitHub API Rate Limit 초과
- **404 Not Found**: 사용자 GitHub 계정 연동 안됨
- **500 Internal Error**: GitHub API 통신 실패

### Caching Strategy
- GitHub API 응답 캐싱 (5분 TTL)
- Rate limit 정보 실시간 업데이트
- 페이지네이션 결과 클라이언트 캐싱
