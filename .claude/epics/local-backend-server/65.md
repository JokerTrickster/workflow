## Summary
Initialize Go project with clean architecture structure, dependency management, and basic configuration setup for the local backend server.

## Acceptance Criteria
- [ ] Go module initialized with proper module name and version
- [ ] Clean architecture folder structure created following Go conventions
- [ ] Core dependencies added (gin, gorm, sqlite, viper for config)
- [ ] Basic configuration files created with environment support
- [ ] Project builds successfully without errors

## Technical Details

### Implementation Approach
1. Initialize Go module in backend directory
2. Create clean architecture folder structure:
   ```
   backend/
   ├── cmd/server/          # Application entry point
   ├── internal/
   │   ├── domain/          # Domain layer (entities, interfaces)
   │   ├── usecase/         # Use cases/application layer
   │   ├── repository/      # Data access layer
   │   ├── delivery/        # Presentation layer (HTTP handlers)
   │   └── infrastructure/  # External concerns (DB, config)
   ├── pkg/                 # Public packages
   └── configs/             # Configuration files
   ```
3. Add core dependencies via go.mod
4. Create basic configuration structure with YAML/JSON support
5. Add environment-specific config files (dev, test, prod)

### Dependencies to Add
- `github.com/gin-gonic/gin` - HTTP framework
- `gorm.io/gorm` - ORM
- `gorm.io/driver/sqlite` - SQLite driver
- `github.com/spf13/viper` - Configuration management
- `github.com/joho/godotenv` - Environment variables

### Configuration Structure
- Database connection settings
- Server configuration (port, host)
- Logging configuration
- Environment-specific overrides
